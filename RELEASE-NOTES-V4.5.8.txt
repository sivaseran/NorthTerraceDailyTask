AGREED BEHAVIOUR
- A new standalone Date Only task may be created for today through today+90 calendar days, inclusive.
- A one-day change (including assignee edits and one-off cancellation) to an existing task may be saved only for that same rolling 90-day period.
- The limit applies to both the desktop Weekly Editor and older Day Editor, with validation again in the Firestore save functions.
- Permanent recurring schedules and their manager-selected effective dates are NOT limited to 90 days. They continue normally until edited or ended.
- For a future recurring change, review existing one-day exceptions only from its effective date to effective date+90 days, inclusive. Within that period the Manager keeps the choice to KEEP or REPLACE reviewed exceptions.
- Any existing exceptions outside the review period are preserved: even choosing Replace does NOT erase them. Existing completed/cancelled and historic records remain protected.
- Pending future occurrences outside the review period pick up the latest recurring template when their date is reconciled/opened; explicit existing date-only exceptions are still preserved.
- Sunday default rotation stays unchanged, unless the manager explicitly changes that task's recurring assignee. Bulk recurring assignee changes now also set the appropriate override flag.
- Legacy Day Editor future-save path preserves date-only exceptions rather than silently clearing today's.
- Compliance future recurrence review also uses the 90-day window.

DEFINITION OF 90 DAYS
The cutoff is TODAY + 90 calendar days (local device date). For example on 18 October 2026, Date Only is allowed through 16 January 2027 inclusive. The rule rolls over each day.

FIREBASE & PERFORMANCE NOTE
No Firebase collection, stored task or historical record is deleted or migrated. For ordinary recurring templates, the index-free query still fetches documents belonging to the *selected template(s)* and filters/reconciles by the 90-day window; it does not yet bound Firestore network reads by date. This avoids introducing a new composite index requirement and does not guarantee a reduced number of database reads. The V4.5.7 12-second review timeout remains in place. Compliance queries themselves now use a 90-day date range.
